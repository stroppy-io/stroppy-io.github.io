# Stroppy Docs

Documentation site for [Stroppy](https://github.com/stroppy-io/stroppy), a
Go-native database stress-testing CLI. Docusaurus 3.10.2, React 19, TypeScript.

## Commands

Use the Node/npm versions declared by `package.json` and the deploy workflow.
Isolation in a container or VM is recommended for build dependencies, but is not
required. Local npm works with the same commands:

```bash
npm ci
npm run check-toolchain # compare installed node/npm against what this repo prescribes
npm run start          # development server, no local search/llms output
npm run sync-changelog
npm run sync-kit       # fetch the Stroppy UI kit pinned in kit.json into src/kit
npm run typecheck
npm run build          # production build under ./build
npm run serve
```

`prestart` and `prebuild` fetch the UI kit (skipped when `src/kit` already has
the pinned version) and refresh `docs/changelog.md` from Stroppy main.
Search and `llms.txt`/`llms-full.txt` are generated only by production builds.

## Running npm

Everything that runs npm or node runs in a disposable VM or container, never on
the host. Two reasons: `npm ci` runs install scripts from dependencies in the
lockfile (`@swc/core`, `core-js`, `fsevents` today), and the lifecycle hooks
above reach the network and write into the tree. The sandbox needs the network
for exactly that: the kit tarball and the upstream changelog are downloads.

`npm run serve` is the exception in the other direction - it only serves an
existing `build/`. Building in the sandbox and serving that directory on the host
with a plain static file server, no node involved, is the cheap way to look at a
change. This tree has been built in firecode, a Firecracker microVM runner over
the project directory; any equivalent VM or container satisfies the rule, the
isolation does, not the tool.

## Merge gate

The merge queue runs these in a branch's worktree, after rebasing it onto `next` and
before landing it; the first that fails parks the branch. It reads this file from `next`,
so a branch cannot change its own gate. `npm ci` and `sync-kit` need the network:
`sync-kit` downloads the UI kit pinned in `kit.json`, and `typecheck` fails without it
because `src/kit` is generated, not committed (`build`'s `prebuild` reruns it, skipped
when the pinned version is already there).

```sh
npm ci
npm run sync-kit
npm audit --omit=dev --audit-level=critical
npm run typecheck
npm run build
```

## Deployment

Pushes to `next` run `.github/workflows/deploy.yml` and deploy `build/` to
GitHub Pages at https://stroppy.io. Scheduled builds refresh the upstream
changelog twice daily.

## Versioning

- `docs/` is current development (`/docs/next/`).
- `versioned_docs/version-X.Y.Z/` stores frozen releases.
- `versioned_sidebars/version-X.Y.Z-sidebars.json` stores frozen navigation.
- `versions.json` orders released documentation.
- `docusaurus.config.ts` `lastVersion` serves the default `/docs/` route.

Cut a version after current docs and `sidebars.ts` are final:

```bash
npm run sync-changelog
npm run docusaurus -- docs:version X.Y.Z
node scripts/slice-version-changelog.mjs X.Y.Z
```

Then update `lastVersion`, run typecheck/build, and verify older snapshots have
no diff. Never edit generated `docs/changelog.md` or a frozen changelog by hand.

## Content policy

- Current and newest-version docs must match released Stroppy behavior.
- Pin source links in frozen release docs to the corresponding Stroppy tag.
- Keep old versioned docs and benchmark prose historical.
- Blog prose is historical; only repair links, pinning product/docs targets to
  the release discussed by the article.
- Do not advertise a companion integration as v6-compatible until its own code
  supports v6.

## Touch and small screens

- Every `:hover` that changes how something looks sits in
  `@media (hover: hover) and (pointer: fine)`, so it does not stick after a
  tap. Only `text-decoration: none` against Infima's link underline stays
  outside.
- Under `(pointer: coarse)` a control is at least 40px tall (2.5rem), grown
  with padding or a stretched `::after`, not with a bigger text.
- Fields are 16px under `(pointer: coarse)`, or iOS zooms into them.
- The tap highlight, `touch-action` and `user-select` baseline is in
  `src/css/custom.css`.
- Nothing scrolls the page sideways at any width: a wide thing (a table, a
  terminal) scrolls in its own box. Such a box is positioned when it holds
  absolutely placed children (the `.sr` screen-reader text): otherwise they
  escape its clip, and phones zoom the whole page out. Desktop Firefox and
  `html { overflow-x: hidden }` hide this, so measure absolute elements
  past the right edge, not `scrollWidth`.
- Check 360, 390, 768, 996 and 997 wide (the Docusaurus breakpoint), and a
  tablet both ways, in both themes.

## UI kit

The site's look is the Stroppy UI kit, published as `stroppy-kit-<version>.tar.gz`
on [stroppy-cloud releases](https://github.com/stroppy-io/stroppy-cloud/releases).
`scripts/sync-kit.mjs` downloads the version pinned in `kit.json`, checks its
sha256, and writes two generated, gitignored directories:

- `src/kit/` — the bundle: `tokens.css` (`--st-*`, dark unless
  `data-theme="light"`), `fonts.css` with Inter and Roboto Mono, `base.css`
  (opt-in, everything scoped to `.st-doc`), `logo/`, `chart.js`, README.
- `static/kit/` — `mark-light.svg` and `mark-dark.svg`, the mark with the kit
  variables resolved, for places that load it as an image (navbar, social
  card); `favicon.svg`, Stroppy Cloud's `web/public/org-logo.svg` at the same
  tag, so both sites share one icon (sha256 pinned as `faviconSha256`).

`docusaurus.config.ts` loads `tokens.css`, `fonts.css`, `base.css`, then
`src/css/custom.css`, which maps Infima's `--ifm-*` onto `--st-*`. Docusaurus
and the kit switch on the same `data-theme` attribute. Colours come from the
kit only: style through `--st-*`, never a literal colour. Prose keeps a
reading size (15px) rather than the kit's 14px app base.

To move to a new kit release, put its version and sha256 in `kit.json` and run
`npm run sync-kit`. To try an unreleased bundle (`make kit-bundle` in
stroppy-cloud), run `KIT_SOURCE=path/to/stroppy-kit-X.tar.gz npm run sync-kit`;
`--force` refetches the pinned release.
